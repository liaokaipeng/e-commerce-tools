# 监控大屏（多店巡检 · 三级告警）

> 本文档面向**使用者**（店铺运维）：说明监控大屏看什么、怎么用、告警怎么读、遇到问题怎么处理，文末附后续待办（Roadmap）。
> 开发视角的架构/接口实测形态见《[架构](架构.md)》第 6.2、6.3、8 节；接入官方 API 的方式见《[新手入门指南](../新手入门指南.md)》「开放平台登录」。

## 1. 这是什么

对「开放平台」已授权的 Shopee 店铺定时巡检，自动采集**订单履约 / 商品库存 / 账户健康**三个域的数据，用规则引擎产生 **P0（紧急）/ P1（重要）/ P2（提醒）**三级告警，在深色大屏上分级展示。本期告警**只在大屏展示**（不接 IM 推送）。

**使用前提**：先在门户页「开放平台」Tab 完成 App 配置（partner_id / partner_key）与店铺授权。主账号授权一次即可带回该账号下全部店铺，无需逐店配置。

## 2. 打开与使用

1. 双击 `启动.bat`（或 `node server/main.js`）启动工具，打开门户页 →「监控大屏」Tab。
2. 授权店铺后**打开大屏即自动开始巡检，无需任何额外设置**；打开页面的瞬间立即补一轮采集。
3. **按需采集**：只有监控大屏页面打开时才会巡检；切到其它 Tab、关闭页面或最小化浏览器即暂停采集（心跳超时自动兜底），回到大屏立即续采。黑窗口（或常开机器）保持运行才有数据与告警；数据落盘本机，重启后继续积累。

大屏布局与操作：

| 区域 | 内容 | 操作 |
|------|------|------|
| 顶栏统计卡 | 店铺数 / P0 / P1 / P2 / 正常（另有「未监控」「待重新授权」按需出现） | P0 卡片红色脉冲；可开关「投影」（大字深色模式）、「声音」（P0 双响提醒）、「轮播」（投影下每 20 秒轮换店铺） |
| 店铺健康墙（左） | 每店一张卡片：告警徽章、三域最近采集时间 | 卡片颜色 = 该店最高未关闭告警级别，自动按 P0→P1→P2→正常置顶；点击聚焦该店（卡片底部可看最近采集错误） |
| 趋势 + 矩阵（中） | 7 天趋势曲线（SVG，画 P0/P1/P2 阈值虚线）+ 12+ 店 × 8 指标对比矩阵 | 点店铺卡或矩阵行切换店铺；单元格底色 = 该指标当前告警级别，**红框 ✗ = 该域最近采集失败（悬浮看原因）**，`—` = 平台暂无该数据（不算比例）；点单元格看该店该指标趋势 |
| 告警流（右） | 按 P0→P1→P2 排序的告警列表 | 每条可「确认」「关闭」；指标回稳自动标「✓已恢复」；可按级别过滤 |
| 底部 | P0/P1 跑马灯 + 全局采集状态（巡检运行中/待机/停止、采集中数量） | 采集失败看左侧店铺卡的三域状态（红字 ✗N次） |
| 告警规则面板 | 11 条规则的启用开关与三级阈值 | 「告警规则」按钮打开；修改立即生效并持久化，留空的级别不触发 |
| 监控店铺面板 | 已授权店铺的监控开关 | 「监控店铺」按钮打开；未勾选的店铺不采集、不进大屏（见下） |

「立即采集」按钮：手动触发所选店铺（或全部已启用监控的店铺）立即巡检一轮。

**只想监控部分店铺**：点顶栏「监控店铺」打开配置面板——已授权店铺默认全部监控，取消勾选不需要的即可。未勾选的店铺**不再巡检采集、不出现在大屏**，其未关闭告警自动关闭（历史快照与告警记录保留），重新勾选立即恢复。顶栏「未监控」统计卡显示停用数量，点击可直接打开面板；新授权的店铺默认监控。

## 3. 监控指标（3 个域 · 11 项）

| 域（频率） | 指标 | 含义 | 默认阈值 P2 / P1 / P0 |
| ------------- | -------- | ---------------------------- | ----------------- |
| 订单履约（每 10 分钟） | 今日待发货 | 今天创建的待发货订单数 | 5 / 15 / 30 单 |
| | 昨日及更早待发货 | 昨天及更早创建、仍未发货的订单数 | 3 / 8 / 15 单 |
| | 待处理取消申请 | 买家取消申请待响应的订单数 | 3 / 8 / 15 单 |
| | 首公里未交接 | 打单后未交付 SLS 转运仓的订单数（跨境特色） | 5 / 15 / 30 单 |
| 商品库存（每 30 分钟） | 断货商品 | 全部型号库存合计为 0 的商品数 | 3 / 10 / 25 个 |
| | 低库存商品 | 合计库存 ≤5 件的商品数 | 10 / 30 / 60 个 |
| | 问题商品数 | 官方「有问题的 listing」清单数量（违规/禁卖等） | 1 / 3 / 8 个 |
| 账户健康（每 60 分钟） | 迟发货率 | 平台周口径迟发货率（%） | 2 / 3.5 / 5 % |
| | 未完成率 | 取消+退货退款率（%） | 3 / 5 / 8 % |
| | 店铺评分 | 5 分制，**越小越差** | 4.5 / 4.2 / 4.0 分 |
| | 扣分记录数 | 官方扣分历史记录条数 | — / 1 / 3 条 |

口径说明（与卖家中心看到的可能有细微出入，属正常）：

- **待发货分桶按天估算**：官方订单列表接口不返回创建时间，只有订单号；订单号前 6 位是 YYMMDD 日期，故按「今天 / 昨天及更早」两档估算（无法精确到小时）。
- **库存按商品粒度合计**：一个商品的库存 = 其全部型号之和（避免停产变体把断货数撑爆）；为控制接口调用量，每轮抽查**最近更新的 50 个热点商品**，非全量盘点。
- **迟发货率/未完成率单位为百分数**，与阈值直接比较（3.5 即 3.5%）。

所有阈值都可在「告警规则」面板按你的店铺实际水平调整。

## 4. 三级告警

**级别定义**

| 级别 | 含义 | 视觉 | 响应建议 |
|------|------|------|----------|
| P0 紧急 | 正在造成损失或威胁账户（大量断货/严重积压/采集长期失联） | 红色，置顶闪烁 + 声音 | 立即处理（分钟级） |
| P1 重要 | 业务受损正在发生 | 橙色，置顶 | 当日处理（小时级） |
| P2 提醒 | 趋势性风险、观察项 | 黄色 | 关注即可 |

**生命周期**：触发 → 同店同规则去重计数（显示 ×N）→ 数值恶化自动升级 → 指标回稳自动标「✓已恢复」→ 人工「确认 / 关闭」。P2 持续 24 小时未恢复自动升 P1；人工关闭后再触发会重新打开并计数。

**系统自检告警**（监控自身的监控）：某店采集连续失败 1 次 → P2、2 次 → P1、5 次 → P0；恢复采集后自动标记恢复。常见原因是授权失效，见下节。

**授权失效（待重新授权）**：官方确认凭证死透（access_token 无效、refresh_token 与店铺不匹配等）时，工具把这些店铺标记为「需重新授权」并**自动暂停其采集**（不再每轮巡检打失败请求），店铺卡片置灰显示「待重新授权」，顶部横幅统计待重新授权店铺数并附一键跳转「开放平台」按钮。重新授权成功后**立即恢复采集**（授权回调即时通知调度器刷新店铺列表，无需等待巡检周期）。

## 5. 数据与隐私

- 数据仅存本机 `server/data/monitor/`（gitignored）：`snapshots/`（原始采样，保留 90 天）、`alerts.json`（告警）、`rules.json`（阈值覆盖）、`config.json`（监控店铺排除名单）、`meta.json`（店铺名与采集状态）。
- 不含任何凭证、不含买家敏感信息（订单只统计数量、不落单号明细）。
- 采集全部走只读查询接口，不会改动店铺任何数据。

## 6. 常见问题

- **大屏提示「尚未配置开放平台 App / 没有已授权店铺」**：去「开放平台」Tab 配置 App 并完成店铺授权，大屏会自动开始巡检。
- **店铺显示「采集连续失败」或「待重新授权」（提示 access_token 无效 / refresh_token 与店铺不匹配）**：授权已失效。到「开放平台」Tab 重新生成授权链接、主账号登录授权一次，全部店铺即恢复（无需逐店操作，授权成功后大屏立即恢复采集）。原因：主账号共享 token 被某个店铺的刷新操作绑定后，其余店铺需重新授权（官方 FAQ138 Q8 语义）。
- **告警数与卖家中心不完全一致**：见第 3 节口径说明（按天估算、抽查 50 个热点商品、平台口径快照）；阈值不贴合可直接在规则面板调整。
- **只想监控重点店铺**：用顶栏「监控店铺」面板取消勾选不需要的店铺（不采集、不进大屏，未关闭告警自动关闭，重新勾选即恢复）；确定完全不再使用的店铺也可在「开放平台」Tab 删除其授权。
- **机器不常开**：巡检只在「服务运行 + 大屏页面打开」时进行；重新打开大屏后立即补一轮采集，历史快照不丢。
- **某店某域长时间 ✗**：悬浮店铺卡底部的三域状态看最近错误；多为该店授权问题或网络问题，先按第二条重新授权。

## 7. 后续待办（Roadmap）

按优先级排列，随时可做：

1. **广告域接入**：小时级花费 / ROAS / CPC 异常（`ads/get_all_cpc_ads_hourly_performance`）、广告余额不足预警（`ads/get_total_balance`）。
2. **账户健康补充**：处罚记录（`account_health/get_punishment_history`，需 punishment_status 参数）、问题商品明细（`get_listings_with_issues` 的 listing_list）。
3. **资金域接入**：打款延迟/冻结异常（`payment/get_escrow_list` / `get_payout_detail`）、钱包流水核对（`get_wallet_transaction_list`）。
4. **售后评价域**：退货申请量按原因聚合突增（`returns/get_return_list`）、差评关键词突增（`product/get_comment`）。
5. **智能基线**：静态阈值之外加同环比 + Z-score(3σ) 检测（需先积累 7 天以上快照；基础设施已就绪：快照按天分文件、读取函数现成）。
6. **库存监控增强**：轮转抽查覆盖全量商品、爆款标记（重点品断货直接 P0）、全球商品库存（`global_product/*` 为 merchant 作用域，签名形态已探明但需验证 token 用法）。
7. **WebHook 实时事件**：订单/商品状态秒级推送（需公网回调地址，本地部署可配合 `push/get_lost_push_message` 兜底补拉）。
8. **告警报表导出**：按周/月导出告警历史 Excel（复用已有 exceljs 依赖）。
9. **授权长效化**：已验证官方语义（FAQ138 Q8：主账号共享 token 被任一店铺刷新后即不再共享），当前策略为共享组到期经 merchant_id 整组续期（`planRefresh`/`refreshTokenWithMerchant`），失败则整组标记需重新授权；后续可进一步验证 merchant_id 续期的实际成功率（需重新授权后积累实测），或推动每店单独授权以彻底摆脱共享 token 限制。
