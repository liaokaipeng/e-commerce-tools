# 架构文档

> 面向**开发者**：总体架构、目录结构、API 路由总表与后端约定。三条长链路的实现详解见《[视频上传链路](视频上传链路.md)》《[开放平台链路](开放平台链路.md)》《[监控大屏实现](监控大屏实现.md)》。

## 1. 总体架构

单服务、单端口（8765）、单网页：一个 Node 后端托管前端构建产物并注册全部 API；前端为 Vue3 + Element Plus 多页应用，门户页按 Tab 切换各工具、开放平台与监控大屏；一个 MV3 扩展向本地服务推送凭证。技术栈详见 `AGENTS.md` 速查。

```
浏览器（Edge / Chrome）
   ├─ 门户页 + 工具页 + 监控大屏（frontend/dist，由后端托管）
   └─ 扩展「KP工具合集助手」（extension/）：推送 Cookie / 凭证
           ▼
本地 Node 服务 server/main.js（http://127.0.0.1:8765）
   ├─ tiktok.js       TikTok 无水印下载
   ├─ bidding.js      Shopee 竞价导出
   ├─ bidding-cancel.js  Shopee 取消竞价
   ├─ hotlisting-cancel.js  Shopee 取消注册 Hot Listing
   ├─ product-export.js  Shopee 跨境商品数据导出（规格行 + SKU 图片链接）
   ├─ video.js        视频批量上传（链路拆到 video/）
   ├─ openapi.js      开放平台登录（链路拆到 openapi/）
   ├─ monitor.js      多店监控大屏（链路拆到 monitor/）
   └─ cache.js        缓存清理（扩展 popup 按类别调用）
           │ 出站请求（server/lib/http.js）
           ▼
       Shopee / TikTok 线上接口
```

## 3. 后端分层与约定

- **路由注册与链路分离**：业务模块导出 `register({ get, post })`，由 `main.js` 启动前统一调用并入「方法 + 路径」路由表；链路较长的模块入口只留路由注册，常量 / 出站 / 解析 / 编排拆到同名子目录。
- **通用能力下沉 `lib/`**：`sendJson` / `readBody` / `readJsonBody`（严格解析，非法即抛）/ `readJsonBodySoft`（宽容解析，记 warn 后返回 `{}`，含 BOM 容忍）/ `readRouteBody`（控制类接口用：传 `{ res }` 时非法 body 直接回 400，避免静默返回 `{}` 被误判成参数缺失）/ `serveStatic` / `sse` / `createDispatcher`（路由分发 + 异步错误兜底 500）在 `http-utils.js`；出站统一走 `http.js` 的 `request`——按 host 维护 Cookie 罐（`useJar: true`，罐按 6 小时 TTL 空闲回收，避免长跑进程堆积）、`body` 支持 Buffer / 字符串 / 流、`signal` 可中断。**所有 JSON 请求体一律用 `readJsonBody` / `readJsonBodySoft` / `readRouteBody`，不要再手写 `JSON.parse(await readBody(req))`**（唯一例外：`/api/cookie` 为扩展对接协议，返回纯文本）。
- **长任务统一走 `jobs.js`**：批量操作类任务（取消竞价 / 取消 Hot Listing）的暂停 / 继续 / 取消 / SSE 客户端断开即取消 / TTL 僵尸清理都收敛在这里；执行体只在关键步骤间 `await checkpoint(jobId, isAborted)`——被取消抛 `CancelledError`（执行体据此收尾并广播 `cancelled` 事件）、被暂停则挂起轮询。控制路由对未知 jobId 一律回 404 而非 500。
- **重试退避统一走 `retry.js`**：`retry(fn, { attempts, waitOf, shouldRetry, onRetry, isAborted })` + 三种策略（`exponentialBackoff` 网络/5xx、`fixedBackoff` 上游限流、`jitteredLinearBackoff` 防风控）；`isAborted` 命中时原样抛出（取消不被误判为「行失败」而重试）。
- **CORS 白名单（`main.js` 的 `isAllowedOrigin`）**：只放行本机来源（`http(s)://127.0.0.1|localhost[:端口]`，含 Vite 开发服务器）与浏览器扩展（`chrome-extension://` / `moz-extension://`）；其余带 `Origin` 的请求直接 403，无 `Origin`（扩展 / 同源）不写 CORS 头。**不要退回 `Access-Control-Allow-Origin: *`**——那会让任意网页能对本机写接口发跨源请求。
- **卖家中心接口调用统一走 `shopee-session.js`**：`buildShopeeUrl`（拼公共查询参数）、`apiGet` / `apiPost`（带 Cookie/UA/Origin/Referer，统一断言登录失效与业务码非 0）、`fetchShopRegion`（返回小写市场，失败空串；调用 `cbsc_shop_region` 的模块回落 `DEFAULT_REGION`）。竞价导出、取消竞价、取消 Hot Listing、商品导出**不得再各自复制**上述函数或硬编码 `https://seller.shopee.cn`。
- **导出落盘统一走 `export-utils.js`**：`ensureDir`（默认落用户「下载」目录）、`timestampText`（`YYYY-MM-DD_HHmmss`）、`styleExcelHeader`（表头加粗居中 + 冻结首行）。
- **凭证不入库**：`bidding-session.json` / `video-session.json` / `openapi-session.json` / `settings.json` 统一存 `server/data/`（gitignored）；日志不完整打印 Cookie / Authorization / token；partner_key 与 token 对外一律 `maskToken` 打码。
- **端口固定 8765**（扩展与文档已硬编码）：`lib/config.js` 区分监听端口 `LISTEN_PORT`（默认 8765，可用 `PORT` 环境变量覆盖，仅供测试/调试）与 OAuth 回调端口 `CALLBACK_PORT`（固定 8765，不随监听端口变化）；两者不一致时 `main.js` 启动即告警。改入口 / 端口 / 结构时，同步更新 `启动.bat`、本文件、`AGENTS.md` 与涉及链路的文档。

## 4. 前端

Vue3 + Element Plus + Vite 多页应用（监控大屏折线图用 ECharts），九个入口在 [vite.config.js](../frontend/vite.config.js) 的 `rollupOptions.input` 登记，构建到 `frontend/dist` 由 `main.js` 托管。

- 路径映射：`/` → 门户页，`/tiktok/` `/bidding/` `/bidding-cancel/` `/hotlisting-cancel/` `/product-export/` `/video/` `/openapi/` `/monitor/` → 工具页（`http-utils.js` 的 `DIR_INDEX`）。
- 九个入口统一经 `src/bootstrap.js` 挂载（Element Plus 注册 + `#app`）；tiktok / bidding / bidding-cancel / hotlisting-cancel / product-export / video / openapi 共用 `styles/base.css` 与 `components/`（LogPanel / DirRow / LoginCard / StorePicker）。
- 共享逻辑：tiktok / bidding / bidding-cancel / hotlisting-cancel / product-export / video 共用 `useToolPage.js`（日志 / 默认目录 / 日志滚动 / SSE 读取 + `runSSE` 统一请求样板），bidding / bidding-cancel / hotlisting-cancel / product-export 共用 `useShopeeSession.js`（登录轮询 + 店铺勾选），新增工具页优先复用。
- 监控大屏页（`src/monitor/`）内部分层：**状态与数据层在 `useMonitor.js`**（含接口调用、SSE、在场心跳、投影轮播），展示拆 `MonitorHeader` / `ShopWall` / `CenterPanels` / `AlertStream` / `MonitorFooter` / `MonitorDrawers` 六个组件（`CenterPanels` 自持 ECharts 实例与 resize 监听），常量与纯函数在 `constants.js`、趋势图 option 在 `trend-chart.js`；`App.vue` 只做编排。样式 `monitor.css` 为**页面级（非 scoped）**——monitor 是独立 HTML 文档不会外泄，共用类（`.panel` / `.stat` / `.b-P0` …）只定义一次，`.proj` 投影模式的后代选择器可跨组件生效。
- 视频上传拆「跨境」「本土」两个 Tab，共用 `/video/` 页面，经 `?mode=cn|ph` 固定站点；开放平台页为 App 配置 / 授权链接 / Token 管理；监控大屏页为深色三栏（健康墙 / 趋势矩阵 / 告警流）+ ECharts 折线 + SSE 推送（详见对应链路文档）。

## 5. 浏览器扩展

一个 MV3 扩展（`extension/`）同时负责两类凭证：

- **竞价**：popup 点按钮 → 推 Cookie 到 `/api/cookie`，存 `bidding-session.json`。
- **视频上传**：`background.js` 监听 `webRequest`，按站点（`shopee.cn` / `shopee.ph`）抓 `Authorization` / `Cookie` / `shop_id` / `userId` → 推 `/api/creds`，存 `video-session.json`；凭证同时缓存 `chrome.storage.local`（服务未启动不丢），抓到新请求时**整包重推**。
- **缓存清理**：popup「缓存清理」区按类别清空——扩展自身缓存走 `runtime` 消息（内存 `credsBySite` + `chrome.storage.local` 一起清，只清存储会被内存写回）；服务端四类（video / bidding / openapi / monitor）走 `POST /api/cache/clear`。视频页每 5s 轮询 `/api/creds`，发现服务端某站点为空时自动清页面内存与 `localStorage` 镜像。

注意：`manifest.json` 的 `host_permissions` 与 `FILTER` 需覆盖对应 `shopee.{cc}` 域；`detectSite` 忽略 `shopee.sg`。
