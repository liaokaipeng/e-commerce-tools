# 架构文档

> 面向**开发者**：说明仓库的总体架构、目录结构、模块职责，以及视频上传与浏览器扩展两条关键链路。
> 面向最终用户的操作见《[新手入门指南](../新手入门指南.md)》；监控大屏的使用与后续待办见《[监控大屏](监控大屏.md)》；仓库概览与快速开始见 [README.md](README.md)；开发流程与测试见《[开发指南](开发指南.md)》；Shopee 开放平台接口资料见 [shopee_api_doc/README.md](../shopee_api_doc/README.md)。

## 1. 总体架构

单服务、单端口（8765）、单网页的本地 Node HTTP 服务。一个后端进程托管前端构建产物并注册全部 API；前端为 Vue3 + Element Plus 多页应用，门户页按 Tab 切换四个工具、开放平台登录与监控大屏；一个浏览器扩展（MV3）负责向本地服务推送两类凭证。

```
浏览器（Edge / Chrome）
   ├─ 门户页 + 工具页 + 监控大屏（frontend/dist，由后端托管）
   └─ 扩展「KP工具合集助手」（extension/）
          │ 推送 Cookie / 凭证
          ▼
本地 Node 服务 server/main.js（http://127.0.0.1:8765）
   ├─ tiktok.js   TikTok 无水印下载
   ├─ bidding.js  Shopee 竞价导出
   ├─ bidding-cancel.js  Shopee 取消竞价（待改进竞价批量撤销）
   └─ video.js    Shopee 视频批量上传（链路拆到 video/）
   ├─ openapi.js  Shopee 开放平台登录（App 授权 + Token 管理，链路拆到 openapi/）
   └─ monitor.js  多店监控大屏（巡检采集 + 三级告警，链路拆到 monitor/）
          │ 出站请求（server/lib/http.js）
          ▼
      Shopee / TikTok 线上接口
```

各工具链路：

| 工具 | 后端模块 | 前端页面 | 链路 |
|------|----------|----------|------|
| TikTok 无水印下载 | `server/tiktok.js` | `frontend/src/tiktok/` | 直连解析页面水文数据 → 第三方接口兜底 → 分地址下载 |
| Shopee 竞价导出 | `server/bidding.js` | `frontend/src/bidding/` | 扩展推 Cookie → 调 seller 接口拉获胜数据 → ExcelJS 导出 |
| Shopee 取消竞价 | `server/bidding-cancel.js` | `frontend/src/bidding-cancel/` | 与导出共用 Cookie → `get_item_ongoing_list(page_tab=2 待改进)` 拉列表 → `seller_withdraw(bid_id)` 逐条撤销 |
| Shopee 视频批量上传 | `server/video.js` | `frontend/src/video/` | 扩展抓凭证 → preupload/分片/PUT/merge/report → video/create 发布 |
| Shopee 开放平台登录 | `server/openapi.js` | `frontend/src/openapi/` | 录入 App（partner_id/partner_key）→ `auth_partner` 生成授权链接 → 卖家授权回调 `/openapi/callback` → `auth/token/get` 换 token 本地持久化 → `access_token/get` 刷新 |
| Shopee 多店监控大屏 | `server/monitor.js` | `frontend/src/monitor/` | 定时巡检已授权店铺（订单履约/商品库存/账户健康）→ 快照 + 规则引擎 → P0/P1/P2 三级告警 → SSE 推送大屏 |

## 3. 后端分层与约定

- **模块化路由注册**：业务模块（`tiktok.js` / `bidding.js` / `bidding-cancel.js` / `video.js` / `openapi.js` / `monitor.js`）导出 `register({ get, post })`，由 `main.js` 在启动前统一调用，把路由并入一张路由表后按「方法 + 路径」匹配分发。
- **路由与链路分离**：链路较长的模块（`tiktok.js` / `video.js` / `openapi.js` / `monitor.js`）只保留路由注册，把常量/出站请求/解析/编排等拆到同名子模块目录（`server/tiktok/` / `server/video/` / `server/openapi/` / `server/monitor/`），避免单文件过长。
- **通用能力下沉到 `lib/`**：JSON 响应（`sendJson`）、请求体读取（`readBody`）、静态服务（`serveStatic`）、SSE（`sse`）在 `http-utils.js`；所有出站 HTTP 请求统一走 `http.js` 的 `request`。
- **出站请求封装** `lib/http.js`：按 host 维护 Cookie 罐（`useJar: true` 时自动注入/回写 Set-Cookie，供视频分片上传的多会话链路）；`body` 支持 `Buffer` / 字符串 / `ReadableStream`（大文件流式上传）；`signal` 传入 `AbortSignal` 可中断请求（任务取消用）。
- **凭证不入库**：`bidding-session.json` / `video-session.json` / `openapi-session.json` / `settings.json` 统一存于 `server/data/`，均 gitignored；日志不完整打印 Cookie / Authorization / token；开放平台 partner_key 与 token 对外一律打码（`lib/openapi-utils.js` 的 `maskToken`）。
- 后端一律 CommonJS（`require` / `module.exports`），前端一律 Vue3 SFC，改代码时保持文件原有风格。

## 4. 前端

Vue3 + Element Plus + Vite 多页应用，七个入口在 [vite.config.js](../frontend/vite.config.js) 的 `rollupOptions.input` 登记，构建到 `frontend/dist` 由 `main.js` 托管。

- 页面路径映射：`/` → 门户页，`/tiktok/` `/bidding/` `/bidding-cancel/` `/video/` `/openapi/` `/monitor/` → 工具页（见 `server/lib/http-utils.js` 的 `DIR_INDEX`）。
- tiktok / bidding / bidding-cancel 三页共用逻辑抽在 `src/composables/useToolPage.js`（默认目录设置 / 日志自动滚动 / SSE 流读取），新增工具页优先复用，不重复实现。
- 视频上传按站点拆为「跨境视频上传」「本土视频上传」两个 Tab，共用 `/video/` 页面，经 `?mode=cn|ph` 固定站点。
- 开放平台登录页（`src/openapi/`）：App 配置（partner_id/partner_key/环境）、授权链接生成、已授权店铺的 Token 状态与刷新/删除/测试，每 30 秒自动刷新到期状态。
- 监控大屏页（`src/monitor/`）：深色大屏 + 三栏布局（店铺健康墙 / 趋势图与对比矩阵 / 三级告警流），图表 SVG 自绘零依赖；`/api/monitor/events` SSE 实时推送 + 30s 兜底轮询；P0 红色脉冲置顶 + 声音提醒，P1 橙色、P2 黄色，告警仅在大屏展示（不接 IM）。

## 5. 视频上传链路详解

### 5.1 站点与链路

| 站点 | 键 | 链路 |
|------|----|------|
| 跨境（.cn，覆盖多国） | `cn` | 分片 + merge（域名/参数见 `video/constants.js` 顶部常量与 `CN`） |
| 本土菲律宾（.ph） | `ph` | 单次 PUT + task 发布（域名/参数见 `SITES.ph`） |

上传主流程：`preupload → 分片 upload → mergeFiles → reportupload → item/list → video/create`（跨境）；`ph` 走 S3 单次 PUT 后创建/发布 task。

### 5.2 凭证

- 扩展抓取后推 `/api/creds`，按站点存 `server/data/video-session.json`；`cred.js` 负责读取、写入与兼容旧扁平格式。
- 跨境 `cn` 支持多店铺：`storedCreds.cn = { shops: { [shopId]: { auth, cookie, userid } } }`；本土 `ph` 保持单店铺。
- **跨境凭证解析唯一入口 `resolveCnAuth`**：优先级为本地已抓凭证（账号级通用，取有效期最长者）→ Cookie 换取新凭证 → 报错引导手动上传。因此任一跨境店铺手动上传一次，同账号下所有店铺（含不同国家站点）均可直接批量上传。

### 5.3 加密与签名

- `preupload` 返回的 `access_key` / `token` 为 AES-128-CBC 加密（key = `shopee_vod_` + biz 左补 0 到 5 位，iv 固定），用 `lib/video-utils.js` 的 `decryptVodToken` 解密。
- 跨境 `merge` 需要文件 etag（由 SHA1 算出）；`reportupload` 需要整文件 md5。
- 本土 `ph` 的 S3 PUT 用 `awsSigV4` 签名。
- solutions 系列接口成功码为 `200000`（非 0），有 `post_id` 即发布成功；老接口可能返回 0。

### 5.4 大文件流式处理

全程不整文件 `readFileSync` 进内存：

- 哈希用 `streamHashes`：md5 / sha1 / sha256 一次流式遍历同时产出。
- 跨境分片用 `readChunk` 按 `[start, end)` 段流读（单片峰值 1MB）。
- 本土 PUT 用 `fs.createReadStream` 作 body（sha256 经 `payloadSha256` 预计算，`http.js` 的 `request` 对流式 body 走 pipe）。
- MP4 元信息用 `probeVideoFile` 头尾采样（各 512KB）定位 `moov`，再按偏移只读完整 moov。

### 5.5 Job 与 SSE

- `POST /api/start` 返回 `jobId`，`GET /api/events?jobId=` 接收事件：`row-start` / `step` / `row-done` / `row-error` / `cancelled` / `finished` / `fatal`。
- `job.js` 对每个 job 缓存事件（`jobEvents`，最多缓存 20 个任务、单任务最多 200 条），**迟到连接自动回放**：任务可能在 SSE 连接建立前就结束（如首行校验秒失败），无回放会让前端一直卡在「上传中」。

### 5.6 任务取消

`POST /api/cancel`（body `{ jobId }`）→ 标记 `abortedJobs` + `AbortController.abort()` 中断进行中的请求；`processJob` 在每行开始前与行失败后检查取消标志，广播 `cancelled` 事件（含 `done` 计数）并收尾，不广播 `finished`；取消造成的中断在 `request.js` 的 `call` 中不重试（`signal.aborted` 直接抛）。

### 5.7 行校验

`validateUploadRow`（`lib/video-utils.js`）先于一切网络请求执行，文件不存在等错误秒失败；文案/阈值常量 `CAPTION_MAX_LENGTH` 与前端 `video/App.vue` 的即时预览校验保持一致（前端无文件系统检查，文件是否存在由后端兜底）。

## 6. 开放平台登录链路

### 6.1 授权流程（OAuth）

```
① 录入 App     前端 /openapi/ 页面保存 partner_id / partner_key / 环境（prod 生产 / sandbox 沙箱）
       │ POST /api/openapi/app → server/data/openapi-session.json
       ▼
② 授权链接     POST /api/openapi/auth-url → 本地拼接 GET 授权链接（不发起接口调用）：
       │ partner.shopeemobile.com/api/v2/shop/auth_partner?partner_id=…&timestamp=…&sign=…&redirect=…（约 30 分钟有效）
       │ 浏览器打开 auth_url，卖家登录选店授权
       ▼
③ 回调换 token  官方跳回 redirect 配置的回调地址（主账号授权时只带 code=…&main_account_id=…，**没有 shop_id**）
       │ 内联 HTML 页（server/openapi.js 直接输出）读 query → POST /api/openapi/auth-callback
       ▼
④ 持久化       官方 /api/v2/auth/token/get 返回 access_token（约 4 小时）/ refresh_token（约 30 天）
       │ 主账号授权以 main_account_id 换取（回调无 shop_id 时），返回的 shop_id_list 全部保存（同一对 token 账号级通用）
       │ 按环境分区存入 openapi-session.json
       ▼
⑤ 后续调用     openapi/client.js 的 callOpenApi(apiPath, 业务参数, { shopId })：自动签名 + 附带 token，
               过期自动用 refresh_token 换新（先拿到新 token 再写盘，旧 refresh 立即失效）
```

官方网关：生产 `https://partner.shopeemobile.com`，沙箱 `https://partner.test-stable.shopeemobile.com`；回调 redirect 需与开放平台 App 后台配置一致。**后台对 redirect 做域名校验，不接受 `127.0.0.1` / `localhost` / `sslip.io` 等指向本机的地址（报 Invalid live redirect url domain），且不能带 `?` 查询参数**；实际可保存的是用户自有域名（http/https 均可），没有域名时后台与工具都用默认占位 `https://example.com/`。后端 `validateRedirect` 支持两种模式：`auto`（http + 本机域名白名单 + 8765 + `/openapi/callback`，授权后自动跳回换 token，仅当后台恰好接受这类地址时可用）与 `manual`（任意 http/https 域名：授权后浏览器跳到该地址，用户把地址栏完整链接粘贴回「开放平台」页「手动完成授权」；也可在该域名放转发页 `location.replace('http://127.0.0.1:8765/openapi/callback'+location.search)` 或加一条指向 127.0.0.1 的 A 记录实现全自动）。

### 6.2 签名规则（v2）

- 业务接口：`base = partner_id + api_path + timestamp + access_token + shop_id`（无 token 时不拼后两项）。
- `sign = HMAC-SHA256(partner_key, base)`（小写 hex）；`auth_partner` 特殊：**不发起接口调用**，授权链接在本地直接拼接为 GET URL（partner_id/redirect/sign/timestamp 全在 query，`client.js` 的 `getAuthUrl`）。
- 其余接口方法约定（以官方网关实测为准）：**查询类接口（get_*/search_*，如 get_shop_info）用 GET**——公共参数 + 业务参数全部放 query、无 body；**写操作与换 token 用 POST**——公共参数（partner_id / timestamp / sign，及 access_token / shop_id）放 query、业务参数放 JSON body；方法用错网关直接 404。
- **access_token/get 刷新接口特殊（2026-08 生产实测，与其它接口不同）**：签名 base 只拼 `partner_id + api_path + timestamp`（不拼 token/shop_id）；query 只放 `partner_id/timestamp/sign`；body 为 `{ partner_id: 数字, shop_id: 数字, refresh_token }`——partner_id 与 shop_id 必须为**数字类型**，字符串会报 "the format of xxx parameter is wrong"；网关对失效凭证会返回误导性文案（"Invalid access_token" / "Your refresh token or shop_id is wrong"），client.js 的 `hintOf` 已翻译为「请重新授权」类中文提示。
- `timestamp` 为秒级时间，依赖本机时钟；接口返回 `error_invalid_timestamp` 等业务错误时按 `ERROR_HINTS` 映射为中文提示（client.js）。规则以官方「授权与鉴权」页面为准（open.shopee.com/developer-guide/20）。

### 6.3 路由与复用

- 路由（`server/openapi.js`）：`GET /api/openapi/status`、`POST /api/openapi/app` `/auth-url` `/auth-callback` `/refresh` `/remove-shop` `/test`，以及 `GET /openapi/callback` 回调页；未配置 App 时一律 400 中文提示，自动化测试不触达真实站点。
- **后续功能统一入口**：新模块只需 `require('../openapi/client')` 的 `callOpenApi(apiPath, 业务参数, { shopId })`，签名、token 附带、过期自动刷新均由 client 完成（监控大屏 `server/monitor/` 即首个使用者）；认证类错误自动刷新一次并重试，per-shop 内存锁防并发刷新，**全局串行链**防主账号下多店铺共享 refresh_token 时的并发轮换踩踏。
- **刷新结果店铺绑定（2026-08 实测 + 官方 FAQ138 Q8）**：主账号授权得到的 token 对为账号级通用，但 `access_token/get` 返回的新 token 对**绑定到发起刷新的 shop_id**——其它店铺用它调接口报 Invalid access_token、用它刷新报 "Your refresh token or shop_id is wrong"（跨店刷新与 merchant_id 刷新均实测被网关拒绝）。因此 `saveRefreshResult` 只写回发起刷新的店铺，不跨店传播；其余店铺失效时按提示重新授权（在「开放平台」页重新走一次主账号授权即可全部恢复）。
- **失效凭证自动标记（2026-08）**：client 的 `callOpenApi` 在「刷新后仍报认证错」或「refresh_token 已死透」时把该店铺标记为 `invalid`（store.markShopInvalid），错误文案经 `isAuthDead` 判定；已标记店铺不再发起网络请求（`ensureFresh` 直接抛中文提示），监控调度器对其**停止采集**，大屏以「待重新授权」呈现——避免凭证死透的店铺每轮巡检持续刷失败请求与告警。重新授权成功（auth-callback）或接口调用成功（clearShopInvalid）自动清除标记。
- **共享 token 整组续期（2026-08）**：多店铺共享同一 refresh_token 且同属一个 merchant 时，到期续期走 `refreshTokenWithMerchant`（merchant_id 刷新，官方 FAQ138 Q8 允许），成功则 `saveRefreshResultGroup` 把新 token 对**传播给全组店铺**（避免「首店刷新绑定、其余全灭」）；无 merchant_id / 跨商户的共享组无法整组续期，整组标记需重新授权（`planRefresh` 纯函数决策，`markGroupInvalid` 落标记）。
- 凭证安全：`openapi-session.json` 存 `server/data/`（gitignored）；status 等接口只回打码 token（`maskToken`）；日志只打印 shop_id 与到期时间，不打印 token 全值。

## 7. 浏览器扩展

一个 MV3 扩展（`extension/`）同时负责两类凭证：

- **竞价**：popup 点按钮 → 推 Cookie 到 `/api/cookie`，存 `server/data/bidding-session.json`。
- **视频上传**：`background.js` 监听 `webRequest`，按站点（`shopee.cn` / `shopee.ph`）抓 `Authorization` / `Cookie` / `shop_id` / `userId` → 推 `/api/creds`，存 `server/data/video-session.json`；凭证同时缓存在 `chrome.storage.local`，本地服务未启动不丢，抓到新请求时**整包重推**（因此手动清空 `video-session.json` 后一刷新虾皮页面会被自动写回）。

注意：`manifest.json` 的 `host_permissions` 与 `FILTER` 需覆盖对应 `shopee.{cc}` 域；`detectSite` 忽略 `shopee.sg`（路由/指标域名）。

## 8. 监控大屏链路

### 8.1 采集与告警

- 调度器（`monitor/scheduler.js`）**按需采集**：仅当监控大屏页面打开时才执行巡检（前端每 30s 心跳 `/api/monitor/presence`，服务端 75s 租约超时兜底），离开页面立即停采；在场时每 30s 巡检已授权店铺（**每次巡检都重读授权店铺列表，纯本地无网络开销**），按域间隔入队采集：**订单履约 10 分钟 / 商品库存 30 分钟 / 账户健康 60 分钟**；同店串行、跨店并发 ≤3、失败后按正常间隔退避重试；未配置 App 或无授权店铺时空转，不发任何请求；**凭证已标记失效（需重新授权）的店铺跳过采集**（手动采集同样跳过并给出中文提示），重新授权后立即恢复——授权回调/刷新/删除店铺经 `notifyAuthChanged()` 即时通知调度器刷新店铺列表并补采。大屏页在门户 iframe 内时，门户切换 Tab 经 `postMessage('portal-tab')` 告知启停；直接访问大屏页则页面可见即采、隐藏即停。
- 采集（`monitor/collectors.js`）全部经 `callOpenApi`（GET），接口形态为生产实测：
  - `order/get_order_list`：必填 `order_status + time_range_field + time_from/to + page_size`（时间窗 ≤15 天），`response.order_list` 仅含 order_sn（无时间字段），cursor 翻页；**订单年龄按 order_sn 的 YYMMDD 前缀按天估算**（`orderAgeBuckets`：今日 / 昨日及更早两档）。
  - `first_mile/get_unbind_order_list`：`page_size + cursor`，`response.order_list + more/next_cursor`。
  - `product/get_item_list`：**必填 `item_status`（缺了报 product.error_unknown）+ `update_time_from/to + offset/page_size`**，`response.item`（无库存字段）按 `next_offset` 翻页；库存需逐商品调 `product/get_model_list`（`stock_info_v2.summary_info.total_available_stock`），**按商品粒度合计**（全型号 0=断货、合计 ≤5=低库存），每轮抽查前 50 个热点商品控制调用量。
  - 问题商品数取自 `account_health/get_listings_with_issues` 的 `total_count`；健康指标取自 `account_health/get_shop_performance` 的 `response.metric_list`（`metric_name → current_period`，迟发货率/未完成率单位为百分数直接比较）；扣分记录数取自 `get_penalty_point_history.total_count`。
  - 注：`global_product/*` 为 merchant 作用域接口（签名/凭证形态不同），一期未接入。
- 规则引擎（`monitor/rules.js` + `monitor/engine.js`）：静态阈值三级分级（P0/P1/P2，direction 支持 up/down，阈值缺省则该级不触发）；告警生命周期为触发→去重计数→阈值升级→回稳自动恢复（recovered）→人工确认/关闭，P2 持续 24h 自动升 P1；系统自检告警按连续失败次数定级（1→P2、2→P1、≥5→P0）。告警只在大屏展示（本期不接 IM）。
- 授权失效呈现：店铺被标记「需重新授权」时，调度器关闭其「采集连续失败」告警，大屏顶部横幅显示「N 家店铺待重新授权」并附一键跳「开放平台」Tab 按钮（同源 iframe 经 `parent.postMessage` 切 Tab），店铺卡片置灰显示「待重新授权」徽标；总览 `reAuthCount` 字段供前端直接使用。
- 数据（`monitor/store.js`）：`server/data/monitor/` 下 `rules.json`（用户阈值覆盖）、`alerts.json`（告警全量，防抖落盘）、`meta.json`（店铺名/最新值/采集状态）、`snapshots/{shopId}/{metric}/YYYY-MM-DD.json`（采样，保留 90 天）；全部 gitignored，不含凭证。
- SSE（`/api/monitor/events`）：告警变更 / 采集结果 / 规则更新三类事件，迟到连接自动回放最近 200 条（同 video/job.js 思路）；前端 30s 兜底轮询。
