> 面向**开发者**：总体架构、目录结构、API 路由总表与后端约定。三条长链路的实现详解见《[视频上传链路](视频上传链路.md)》《[开放平台链路](开放平台链路.md)》《[监控大屏实现](监控大屏实现.md)》；新增工具步骤与测试调试见《[开发指南](开发指南.md)》；使用者视角见《[新手入门指南](../新手入门指南.md)》与《[监控大屏](监控大屏.md)》。

## 1. 总体架构

单服务、单端口（8765）、单网页：一个 Node 后端托管前端构建产物并注册全部 API；前端为 Vue3 + Element Plus 多页应用，门户页按 Tab 切换各工具、开放平台与监控大屏；一个 MV3 扩展向本地服务推送凭证。语言 / 依赖清单见 `AGENTS.md`「技术栈速查」，共享层与前端分层的实现细则见本文 §3–§4。

```
浏览器（Edge / Chrome）
   ├─ 门户页 + 工具页 + 监控大屏（frontend/dist，由后端托管）
   └─ 扩展「电商工具箱」（extension/）：推送 Cookie / 凭证
           ▼
本地 Node 服务 server/main.js（http://127.0.0.1:8765）
   ├─ tiktok.js       TikTok 无水印下载
   ├─ bidding.js      Shopee 竞价导出
   ├─ bidding-cancel.js  Shopee 取消竞价
   ├─ hotlisting-cancel.js  Shopee 取消注册 Hot Listing
   ├─ video.js        视频批量上传（链路拆到 video/）
   ├─ openapi.js      开放平台登录（链路拆到 openapi/）
   ├─ monitor.js      多店监控大屏（链路拆到 monitor/）
   ├─ cache.js        缓存清理（扩展 popup 按类别调用）
   └─ update.js       版本与自更新（版本源 + 清单比对 + 一键更新，见 §1.3）
           │ 出站请求（server/lib/http.js）
           ▼
       Shopee / TikTok 线上接口
```

### 1.2 取消类链路要点（取消竞价 / 取消注册 Hot Listing）

两个模块同一模式：**预览（扫描待处理项）+ SSE 执行**，执行中可暂停 / 继续 / 取消（门控走 `lib/jobs.js`，路由见 §1.1）。要点：

- **取消竞价**：`get_item_ongoing_list`（`filter.page_tab=2` 待改进，`page_tab=1` 进行中全部）+ `seller_withdraw`（body `{ bid_id }`）逐条撤销；与竞价导出共用 `bidding-session.json`。
- **取消注册 Hot Listing**：每个店铺配 1 个 SPU ID（单行输入，`parseSpuList` 仍兼容多值），持久化到 `server/data/hotlisting-spu.json`（前端编辑后防抖自动保存）；`POST /api/mkt/buybox/get_rsku_vsku_list`（`from_condition.spu_id` + `search_filter.rsku_status=2` 已注册 + `page_info.offset/limit` 翻页）拉取，`POST /api/mkt/buybox/update_enroll`（body `{ rsku_id, vsku_id, seller_decision: 0 }`）逐条取消注册。
  - **只取消 `seller_decision=1` 且 `qualification_flags=1` 的行**：`seller_decision=0` 是资格异常行（如 stock_unqualified），无法取消注册，必须过滤——前端「扫描为空」多为该 SPU 下已注册行全是异常或 SPU 填错。
  - 公共查询参数：`SPC_CDS_VER=2&SPC_CDS=<Cookie 值>&cnsc_shop_id&cbsc_shop_region`。
- **前端 SPU 配置区只渲染「已选店铺」**（`stores ∩ selected`）——授权店铺会涨到几十上百个，全量平铺等于逼用户长滚动；但提交的 `spuMap` 必须是**全量**：后端 `resolvePerShopSpus` 以 body 的 `spuMap` 为完整状态，少传键就等于删配置。
- **SSE 客户端断开即视为取消**（本地单人工具，关页面＝不想继续），另有 30 分钟 TTL 兜底清理；run 首事件 `start` 下发 `jobId`，控制路由对未知 jobId 回 404 而非 500。

### 1.3 版本与自更新（server/update.js）

目标：使用者双击即用的同时能**及时拿到新版本**——发布方推 zip + 清单，客户端自动检测并在门户页一键更新。

- **版本号唯一源 = 仓库根 `package.json` 的 `version`**（`lib/version.js` 的 `currentVersion`）：打包、前端显示、更新比对三处都读它。`server/build-info.json`（`npm run pack` 生成、不入库）只补 commit 与构建时间。
- **发布流程**（`npm run pack`，脚本 `pack.js`）：按与一键更新**同一份白名单**（`update.js` 的 `COPY_ITEMS`）打出 `build/kp_tools-v<版本>.zip`（不含 node_modules——首次由 `启动.bat` 自动 `npm install`；不含 `server/data`；不含 `docs/`——开发文档，不对外分发），并生成根目录 `update.json` 清单（version / url / **sha256** / notes）。发布 = 把 `update.json` 推到 GitHub 仓库（raw 地址固定）+ zip 作为 **Release 资产**上传（模板在 `pack.js` 顶部 `DOWNLOAD_URL_TEMPLATE`，只填一次）。
- **检测**：客户端读 `server/config/update.json` 的 `manifestUrl`（留空＝关闭，仓库默认留空由发布方填写），启动 5 秒后首检 + 每 6 小时轮询（`startAutoCheck` 只在 `main.js` 真正监听端口后调用，测试 require 时不产生定时器）；单机要换镜像写 `server/data/update-config.json`（data 目录永不被更新覆盖）。检查失败**静默回落上次缓存**（`server/data/update-cache.json`），不影响使用。
- **一键更新链路**：下载（流式 + 同步算 sha256）→ 校验（不一致即终止）→ 解压（**系统自带 tar.exe**，Win10 1803+ 内置 bsdtar；探测不到明确报错降级为手动下载——为守「后端不新增运行时依赖」不引解压包）→ 备份 `server/data` 到 `backup/data-<时间戳>`（gitignored）→ 按 `COPY_ITEMS` 白名单覆盖（`server` 复制时跳过 `data` 子目录；**只覆盖不删除**，node_modules 与用户文件保持原样）→ `package.json` 依赖有差异才 `npm install`（失败只记警告不回滚）。落盘后必须重启服务才生效，接口如实返回 `restartRequired`。
- **扩展是 unpacked 加载**：`extension/` 被更新后需在 `edge://extensions` 点「重新加载」，前端完成提示里已包含这句话。
- ⚠ **`启动.bat` 只在 `frontend/dist` 不存在时才构建**：所以发布包必须直接带 `dist`（pack 已保证）；给源码让对方自行构建的分发方式要先删掉包内 dist，否则对方永远跑旧前端。

## 3. 后端分层与约定

- **路由注册与链路分离**：业务模块导出 `register({ get, post })`，由 `main.js` 启动前统一调用并入「方法 + 路径」路由表；链路较长的模块入口只留路由注册，常量 / 出站 / 解析 / 编排拆到同名子目录。
- **通用能力下沉 `lib/`**：`sendJson` / `readBody` / `readJsonBody`（严格解析，非法即抛）/ `readJsonBodySoft`（宽容解析，记 warn 后返回 `{}`，含 BOM 容忍）/ `readRouteBody`（控制类接口用：传 `{ res }` 时非法 body 直接回 400，避免静默返回 `{}` 被误判成参数缺失）/ `jsonAction`（body 当业务参数传入，内部异常统一回 400）/ `serveStatic` / `sse` / `createDispatcher`（路由分发 + 异步错误兜底 500）在 `http-utils.js`；出站统一走 `http.js` 的 `request`——按 host 维护 Cookie 罐（`useJar: true`，罐按 6 小时 TTL 空闲回收，避免长跑进程堆积）、`body` 支持 Buffer / 字符串 / 流、`signal` 可中断。**所有 JSON 请求体一律用 `readJsonBody` / `readJsonBodySoft` / `readRouteBody`，不要再手写 `JSON.parse(await readBody(req))`**（唯一例外：`/api/cookie` 为扩展对接协议，返回纯文本）。
- **基础件下沉 `lib/`**：JSON 文件读写一律用 `lib/json-file.js`（`readJson` 读不到返回兜底、可选 onError 打日志；`writeJson` 自动建父目录）；日期补零 / 本地日期文本用 `lib/date-utils.js`（`pad2` / `ymd`）；通用延时用 `lib/sleep.js`——不要各模块各写一份。
- **长任务统一走 `jobs.js`**：批量操作类任务（取消竞价 / 取消 Hot Listing / 开放平台批量刷新）的暂停 / 继续 / 取消 / SSE 客户端断开即取消 / TTL 僵尸清理都收敛在这里，三者共用的「按店 / 按组执行 + start/shop-start/shop-done/summary/cancelled/fatal」骨架收敛为 `runShopBatch`（各调用点只注入单店执行与差异文案）；执行体只在关键步骤间 `await checkpoint(jobId, isAborted)`——被取消抛 `CancelledError`（执行体据此收尾并广播 `cancelled` 事件）、被暂停则挂起轮询。控制路由对未知 jobId 一律回 404 而非 500，且**控制路由本身不再手写**：用 `registerControlRoutes(post, basePath)` 一次注册 pause / resume / cancel（body `{ jobId }`，非法 body 回 400），取消竞价、取消 Hot Listing、开放平台批量刷新三处共用。
- **重试退避统一走 `retry.js`**：`retry(fn, { attempts, waitOf, shouldRetry, onRetry, isAborted })` + 三种策略（`exponentialBackoff` 网络/5xx、`fixedBackoff` 上游限流、`jitteredLinearBackoff` 防风控）；`isAborted` 命中时原样抛出（取消不被误判为「行失败」而重试）。
- **CORS 白名单（`lib/cors.js` 的 `isAllowedOrigin` / `applyCors`，`main.js` 仅 require）**：只放行本机来源（`http(s)://127.0.0.1|localhost[:端口]`，含 Vite 开发服务器）与浏览器扩展（`chrome-extension://` / `moz-extension://`）；其余带 `Origin` 的请求直接 403，无 `Origin`（扩展 / 同源）不写 CORS 头。**不要退回 `Access-Control-Allow-Origin: *`**——那会让任意网页能对本机写接口发跨源请求。
- **卖家中心接口调用统一走 `shopee-session.js`**（门面，实现拆 `lib/shopee/`）：`buildShopeeUrl`（拼公共查询参数）、`apiGet` / `apiPost`（带 Cookie/UA/Origin/Referer，统一断言登录失效与业务码非 0）、`fetchShopRegion`（返回小写市场，失败空串；调用 `cbsc_shop_region` 的模块回落 `DEFAULT_REGION`）。竞价导出、取消竞价、取消 Hot Listing**不得再各自复制**上述函数或硬编码 `https://seller.shopee.cn`。
- **导出落盘统一走 `export-utils.js`**：`ensureDir`（默认落用户「下载」目录）、`timestampText`（`YYYY-MM-DD_HHmmss`）、`styleExcelHeader`（表头加粗居中 + 冻结首行）。
- **凭证不入库**：`bidding-session.json` / `video-session.json` / `openapi-session.json` / `settings.json` 统一存 `server/data/`（gitignored）；日志不完整打印 Cookie / Authorization / token；partner_key 与 token 对外一律 `maskToken` 打码。
- **端口固定 8765**（扩展与文档已硬编码）：`lib/config.js` 区分监听端口 `LISTEN_PORT`（默认 8765，可用 `PORT` 环境变量覆盖，仅供测试/调试）与 OAuth 回调端口 `CALLBACK_PORT`（固定 8765，不随监听端口变化）；两者不一致时 `main.js` 启动即告警。改入口 / 端口 / 结构时，同步更新 `启动.bat`、本文件、`AGENTS.md` 与涉及链路的文档。

Vue3 + Element Plus + Vite 多页应用（监控大屏折线图用 ECharts），八个入口在 [vite.config.js](../frontend/vite.config.js) 的 `rollupOptions.input` 登记，构建到 `frontend/dist` 由 `main.js` 托管。

- 路径映射：`/` → 门户页，`/tiktok/` `/bidding/` `/bidding-cancel/` `/hotlisting-cancel/` `/video/` `/openapi/` `/monitor/` → 工具页（`http-utils.js` 的 `DIR_INDEX`）。

## 5. 浏览器扩展

一个 MV3 扩展（`extension/`）同时负责两类凭证：

- **竞价**：popup 点按钮 → 推 Cookie 到 `/api/cookie`，存 `bidding-session.json`。
- **视频上传**：`background.js` 监听 `webRequest`，按站点（`shopee.cn` / `shopee.ph`）抓 `Authorization` / `Cookie` / `shop_id` / `userId` → 推 `/api/creds`，存 `video-session.json`；凭证同时缓存 `chrome.storage.local`（服务未启动不丢），抓到新请求时**整包重推**。
- **缓存清理**：popup「缓存清理」区按类别清空——扩展自身缓存走 `runtime` 消息（内存 `credsBySite` + `chrome.storage.local` 一起清，只清存储会被内存写回）；服务端四类（video / bidding / openapi / monitor）走 `POST /api/cache/clear`。视频页每 5s 轮询 `/api/creds`，发现服务端某站点为空时自动清页面内存与 `localStorage` 镜像。

注意：`manifest.json` 的 `host_permissions` 与 `FILTER` 需覆盖对应 `shopee.{cc}` 域；`detectSite` 忽略 `shopee.sg`。
