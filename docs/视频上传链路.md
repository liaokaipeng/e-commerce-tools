# 视频上传链路（开发视角）

> 面向**开发者**：站点拆分、凭证、加密签名、大文件流式处理、Job/SSE 与任务取消。总体架构见《[架构](架构.md)》；使用者操作见《[新手入门指南](../新手入门指南.md)》「视频批量上传」；测试与调试见《[开发指南](开发指南.md)》。

## 1. 站点与链路

| 站点 | 键 | 链路 |
|---|---|---|
| 跨境（.cn，覆盖多国） | `cn` | 分片 + merge（域名/参数见 `video/constants.js` 顶部常量与 `CN`） |
| 本土菲律宾（.ph） | `ph` | 单次 PUT + task 发布（域名/参数见 `SITES.ph`） |

跨境主流程：`item/list 商品前置校验 → preupload → 分片 upload → mergeFiles → reportupload → video/create`；`ph` 走 `item/list → task/create → S3 单次 PUT → reportupload → task/edit → task/post`。

**商品前置校验与跳过（cn/ph 一致）**：表格行**未配置商品编码**、或**配置了但 item/list 查不到**时，`uploadOneCn/uploadOnePh` 在真正上传前抛 `skipError`（`lib/video-utils.js`），`job.js` 的 `row-error` 事件带 `skip: true`，前端状态列显示「失败，商品为空」，该行**不上传**。cn 的校验②（查不到商品）放在流式哈希与 `resolveCnAuth` **之后**、preupload 之前——「先哈希后解析凭证」顺序不能调（测试依赖首行哈希耗时让 cancel 稳定到达）。

## 2. 凭证

- 扩展抓取后推 `/api/creds`，按站点存 `server/data/video-session.json`，由 `creds.js` 读写。
- 跨境 `cn` 支持多店铺：`storedCreds.cn = { shops: { [shopId]: { auth, cookie, userid } } }`；本土 `ph` 保持单店铺。
- **跨境凭证解析唯一入口 `resolveCnAuth`**：优先级为已抓凭证（账号级通用，取有效期最长者）→ Cookie 换取新凭证 → 报错引导手动上传。因此任一跨境店铺手动上传一次，同账号下所有店铺（含不同国家站点）即可批量上传。

## 3. 加密与签名

- `preupload` 返回的 `access_key` / `token` 为 AES-128-CBC 加密（key = `shopee_vod_` + biz 左补 0 到 5 位，iv 固定），用 `lib/video-utils.js` 的 `decryptVodToken` 解密。
- 跨境 `merge` 需要文件 etag（由 SHA1 算出）；`reportupload` 需要整文件 md5；本土 `ph` 的 S3 PUT 用 `awsSigV4` 签名。
- solutions 系列接口成功码为 `200000`（非 0），有 `post_id` 即发布成功。

## 4. 大文件流式处理

全程不整文件 `readFileSync` 进内存：

- 哈希用 `streamHashes`：md5 / sha1 / sha256 一次流式遍历同时产出；跨境分片用 `readChunk` 按 `[start, end)` 段流读（单片峰值 1MB）；本土 PUT 用 `fs.createReadStream` 作 body。
- MP4 元信息用 `probeVideoFile` 头尾采样（各 512KB）定位 `moov`，再按偏移只读完整 moov。

## 5. Job 与 SSE

- `POST /api/start` 返回 `jobId`，`GET /api/events?jobId=` 接收事件：`row-start` / `step` / `row-done` / `row-error` / `cancelled` / `finished` / `fatal`。
- `job.js` 按 job 缓存事件（`jobEvents`，最多 20 任务、单任务 200 条），**迟到连接自动回放**：任务可能在 SSE 建立前就结束（如首行校验秒失败），无回放前端会一直卡在「上传中」。

## 6. 任务取消

`POST /api/cancel`（body `{ jobId }`）→ 标记 `abortedJobs` + `AbortController.abort()` 中断进行中的请求；`processJob` 在每行开始前与行失败后检查取消标志，广播 `cancelled`（含 `done` 计数）并收尾，不广播 `finished`；取消造成的中断在 `request.js` 的 `call` 中不重试（`signal.aborted` 直接抛）。

## 7. 行校验

`validateUploadRow`（`lib/video-utils.js`）先于一切网络请求执行，文件不存在等错误秒失败；文案/阈值常量 `CAPTION_MAX_LENGTH` 与前端 `frontend/src/video/useVideoTable.js` 即时预览校验保持一致（前端无文件系统检查，文件是否存在由后端兜底）。
