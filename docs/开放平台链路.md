# 开放平台登录链路（开发视角）

> 面向**开发者**：OAuth 授权流程、v2 签名规则、token 刷新与失效语义，以及官方 Open API 的统一调用入口。总体架构见《[架构](架构.md)》；使用者操作见《[新手入门指南](../新手入门指南.md)》「授权店铺」；参数报错排查见《[开发指南](开发指南.md)》5.1 节；官方接口资料见 [shopee_api_doc/README.md](../shopee_api_doc/README.md)。

## 1. 授权流程（OAuth）

```
① 录入 App      /openapi/ 页保存 partner_id / partner_key / 环境（prod 生产 / sandbox 沙箱）
       │ POST /api/openapi/app → server/data/openapi-session.json
       ▼
② 授权链接     POST /api/openapi/auth-url → 本地拼接 GET 授权链接（不调接口，约 30 分钟有效）：
       │ partner.shopeemobile.com/api/v2/shop/auth_partner?partner_id=…&timestamp=…&sign=…&redirect=…
       │ 浏览器打开 auth_url，卖家登录选店授权
       ▼
③ 回调换 token  官方跳回 redirect 配置的回调地址（主账号授权只带 code=…&main_account_id=…，**没有 shop_id**）
       │ 内联 HTML 页读 query → POST /api/openapi/auth-callback
       ▼
④ 持久化       官方 /api/v2/auth/token/get 返回 access_token（约 4 小时）/ refresh_token（约 30 天）
       │ 主账号授权以 main_account_id 换取（回调无 shop_id 时），返回的 shop_id_list 全部保存（同一对 token 账号级通用）
       ▼
⑤ 后续调用     callOpenApi(apiPath, 业务参数, { shopId })：自动签名 + 附带 token，
              过期自动换新（共享 token 组整组换，先拿到新 token 再写盘，旧 refresh 立即失效）
```

官方网关：生产 `https://partner.shopeemobile.com`，沙箱 `https://partner.test-stable.shopeemobile.com`；回调 redirect 需与 App 后台配置一致。**后台只做域名校验**：不接受 `127.0.0.1` / `localhost` / `sslip.io` 等指向本机的地址（报 Invalid live redirect url domain）、不能带 `?` 查询参数；没有域名时后台与工具都用默认占位 `https://example.com/`。`validateRedirect` 支持 `auto`（本机域名白名单 + 8765 + `/openapi/callback`，授权后自动换 token）与 `manual`（浏览器跳到任意域名后，把完整链接粘贴回「开放平台」页；也可用转发页或指向 127.0.0.1 的 A 记录实现全自动）。

## 2. 签名规则（v2）

- 业务接口：`base = partner_id + api_path + timestamp + access_token + shop_id`（无 token 时不拼后两项）。
- `sign = HMAC-SHA256(partner_key, base)`（小写 hex）；`auth_partner` 特殊：**不调接口**，授权链接由本地直接拼接为 GET URL（`client.js` 的 `getAuthUrl`）。
- 方法约定：**查询类接口（get_*/search_*）用 GET**——公共参数 + 业务参数全放 query、无 body；**写操作与换 token 用 POST**——公共参数放 query、业务参数放 JSON body；方法用错网关直接 404。
- **access_token/get 刷新接口特殊（生产实测）**：签名 base 只拼 `partner_id + api_path + timestamp`；query 只放 `partner_id/timestamp/sign`；body 为 `{ partner_id: 数字, shop_id: 数字, refresh_token }`——id 必须**数字类型**（字符串报格式错）；网关对失效凭证返回误导性文案（"Invalid access_token" / "Your refresh token or shop_id is wrong"），`hintOf` 已翻译为「请重新授权」提示。
- `timestamp` 为秒级时间（依赖本机时钟）；`error_invalid_timestamp` 等业务错误按 `ERROR_HINTS` 映射中文提示。规则以官方「授权与鉴权」页面为准（developer-guide/20）。

## 3. 路由与复用

- 路由（`server/openapi.js`，详见《架构》1.1）：`GET /api/openapi/status`、`POST /api/openapi/app` `/auth-url` `/auth-callback` `/refresh` `/remove-shop` `/test`、`POST /api/openapi/refresh-all/run`（SSE 批量刷新）、`POST /api/openapi/refresh-all/pause|resume|cancel`、`GET /openapi/callback` 回调页；未配置 App 时一律 400 中文提示。
- **统一调用入口**：新模块只需 `callOpenApi(apiPath, 业务参数, { shopId })`（查询类传 `{ method: 'GET' }`），签名、token 附带、过期自动刷新均由 client 完成；认证错误**强制刷新**一次后重试（`ensureFresh` 的 `force`：token 名义未过期也要真刷新，否则复用的还是那个坏 token，白跑一遍就把店铺标成需重新授权）。
- **刷新入口只有一条（务必复用）**：`ensureFresh(env, shopId, { force })` 取可用 token（未过期复用 / 过期刷新 / `force` 强制刷新），`refreshShopNow(env, shopId)` 是它的强制版；`POST /api/openapi/refresh`（页面单店「刷新」按钮）、`POST /api/openapi/refresh-all/run`（批量按钮）与 `callOpenApi` 的重试都走它。分组由 `planRefresh` 决策，**新增任何刷新路径都必须复用这两个入口，不要再直接调 `refreshToken`**。
- **批量刷新必须分组去重（`server/openapi/refresh-all.js`）**：开放平台页「批量刷新 token」按钮 → `POST /api/openapi/refresh-all/run`（SSE）。`planRefreshGroups`（纯函数）先按 `refreshToken` 归组，**每组只调一次 `refreshShopNow`**：逐店遍历时第一店刷完就轮换了 token 对，后续店铺拿旧 refresh_token 必然失败，并把整组拖成「需重新授权」。整组已失效 / 缺 refresh_token / 共享但无 merchant_id（无法整组续期）的组直接跳过，事件 `skipped` 带原因，**不额外把店铺标失效**（用户主动点批量刷新不该标死「其实还好」的店铺）；组内优先选未失效店铺当代表，整组续期成功会一并恢复组内的失效标记。任务走 `lib/jobs.js`：SSE 断开即取消，前端「取消」调 `POST /api/openapi/refresh-all/cancel`，组间门控（进行中的那一组会自然跑完）。事件序：`start`（jobId / 总店铺数 / 总组数 / 跳过的组）→ `skipped` / `group-start` / `group-done` → `summary`（或 `cancelled` / `fatal`）。
- **共享 token 组必须整组续期（官方 FAQ138 Q8）**：主账号 token 账号级通用，但 `access_token/get` 返回的新 token 只绑定发起刷新的那个 id。共享组若被**单店**刷新（body 带 shop_id），旧 refresh_token 立即作废、新 token 只归该店，其余店铺随后拿已作废的旧 token 去整组续期 → 整组被判「需重新授权」。因此 `planRefresh` 判定共享同商户时走 `refreshTokenWithMerchant` + `saveRefreshResultGroup`（merchant_id 刷新、新 token 全组传播）；独立凭证才走 `refreshToken` + `saveRefreshResult`（只写回本店）；共享但无 merchant_id / 跨商户时无法整组续期，整组标记需重新授权。
- **per-shop 锁 + 全局串行链**：同一店铺的并发刷新共享同一个 Promise，跨店铺刷新统一排队，防共享 token 轮换时的并发踩踏（页面连点「刷新」也只发一次网关请求）。
- **失效凭证自动标记**：`callOpenApi` / 刷新失败确认凭证死透（`isAuthDead`）后经 `markInvalidByPlan` 标记 —— 独立凭证只标本店，共享 token 组整组标记；已标记店铺不再发请求（`ensureFresh` 直接抛错），监控调度器停止采集、大屏显示「待重新授权」；重新授权或调用成功（`clearShopInvalid`）自动清除。**失效店铺不出现在 `/api/openapi/stores`（各工具「选择店铺」数据源）**，但仍保留在 `/api/openapi/status` 供大屏提示。
- 凭证安全：`openapi-session.json` 存 `server/data/`（gitignored）；status 等接口只回打码 token（`maskToken`）；日志只打印 shop_id 与到期时间，不打印 token 全值。
