# 开放平台登录链路（开发视角）

> 面向**开发者**：OAuth 授权流程、v2 签名规则、token 刷新与失效语义，以及官方 Open API 的统一调用入口。总体架构见《[架构](架构.md)》；使用者操作见《[新手入门指南](../新手入门指南.md)》「开放平台登录」；参数报错排查见《[开发指南](开发指南.md)》5.1 节；官方接口资料见 [shopee_api_doc/README.md](../shopee_api_doc/README.md)。

## 1. 授权流程（OAuth）

```
① 录入 App      /openapi/ 页保存 partner_id / partner_key / 环境（prod 生产 / sandbox 沙箱）
       │ POST /api/openapi/app → server/data/openapi-session.json
       ▼
② 授权链接     POST /api/openapi/auth-url → 本地拼接 GET 授权链接（不调接口，约 30 分钟有效）：
       │ partner.shopeemobile.com/api/v2/shop/auth_partner?partner_id=…&timestamp=…&sign=…&redirect=…
       │ 浏览器打开 auth_url，卖家登录选店授权
       ▼
③ 回调换 token  官方跳回 redirect 配置的回调地址（主账号授权只带 code=…&main_account_id=…，**没有 shop_id**）
       │ 内联 HTML 页读 query → POST /api/openapi/auth-callback
       ▼
④ 持久化       官方 /api/v2/auth/token/get 返回 access_token（约 4 小时）/ refresh_token（约 30 天）
       │ 主账号授权以 main_account_id 换取（回调无 shop_id 时），返回的 shop_id_list 全部保存（同一对 token 账号级通用）
       ▼
⑤ 后续调用     callOpenApi(apiPath, 业务参数, { shopId })：自动签名 + 附带 token，
              过期自动用 refresh_token 换新（先拿到新 token 再写盘，旧 refresh 立即失效）
```

官方网关：生产 `https://partner.shopeemobile.com`，沙箱 `https://partner.test-stable.shopeemobile.com`；回调 redirect 需与 App 后台配置一致。**后台只做域名校验**：不接受 `127.0.0.1` / `localhost` / `sslip.io` 等指向本机的地址（报 Invalid live redirect url domain）、不能带 `?` 查询参数；没有域名时后台与工具都用默认占位 `https://example.com/`。`validateRedirect` 支持 `auto`（本机域名白名单 + 8765 + `/openapi/callback`，授权后自动换 token）与 `manual`（浏览器跳到任意域名后，把完整链接粘贴回「开放平台」页；也可用转发页或指向 127.0.0.1 的 A 记录实现全自动）。

## 2. 签名规则（v2）

- 业务接口：`base = partner_id + api_path + timestamp + access_token + shop_id`（无 token 时不拼后两项）。
- `sign = HMAC-SHA256(partner_key, base)`（小写 hex）；`auth_partner` 特殊：**不调接口**，授权链接由本地直接拼接为 GET URL（`client.js` 的 `getAuthUrl`）。
- 方法约定：**查询类接口（get_*/search_*）用 GET**——公共参数 + 业务参数全放 query、无 body；**写操作与换 token 用 POST**——公共参数放 query、业务参数放 JSON body；方法用错网关直接 404。
- **access_token/get 刷新接口特殊（生产实测）**：签名 base 只拼 `partner_id + api_path + timestamp`；query 只放 `partner_id/timestamp/sign`；body 为 `{ partner_id: 数字, shop_id: 数字, refresh_token }`——id 必须**数字类型**（字符串报格式错）；网关对失效凭证返回误导性文案（"Invalid access_token" / "Your refresh token or shop_id is wrong"），`hintOf` 已翻译为「请重新授权」提示。
- `timestamp` 为秒级时间（依赖本机时钟）；`error_invalid_timestamp` 等业务错误按 `ERROR_HINTS` 映射中文提示。规则以官方「授权与鉴权」页面为准（developer-guide/20）。

## 3. 路由与复用

- 路由（`server/openapi.js`，详见《架构》1.1）：`GET /api/openapi/status`、`POST /api/openapi/app` `/auth-url` `/auth-callback` `/refresh` `/remove-shop` `/test`、`GET /openapi/callback` 回调页；未配置 App 时一律 400 中文提示。
- **统一调用入口**：新模块只需 `callOpenApi(apiPath, 业务参数, { shopId })`（查询类传 `{ method: 'GET' }`），签名、token 附带、过期自动刷新均由 client 完成；认证错误自动刷新一次并重试，per-shop 锁 + **全局串行链**防多店铺共享 refresh_token 时的并发轮换踩踏。
- **刷新结果绑定发起刷新的店铺（官方 FAQ138 Q8 语义）**：主账号 token 账号级通用，但刷新返回的新 token 只绑定发起刷新的 shop_id，跨店使用/刷新会被网关拒绝。因此 `saveRefreshResult` 只写回发起店铺、不跨店传播；其余店铺失效时重新主账号授权即可全部恢复。
- **失效凭证自动标记**：`callOpenApi` 确认凭证死透（`isAuthDead`）后经 `markShopInvalid` 标记店铺 `invalid`——已标记店铺不再发请求，监控调度器对其停止采集、大屏显示「待重新授权」；重新授权或调用成功（`clearShopInvalid`）自动清除。
- **共享 token 整组续期**：多店铺共享同一 refresh_token 且同属一个 merchant 时，到期走 `refreshTokenWithMerchant`（merchant_id 刷新，FAQ138 Q8 允许），成功经 `saveRefreshResultGroup` 全组传播新 token（避免「首店刷新绑定、其余全灭」）；无 merchant_id / 跨商户的共享组无法整组续期，整组标记需重新授权（`planRefresh` 决策）。
- 凭证安全：`openapi-session.json` 存 `server/data/`（gitignored）；status 等接口只回打码 token（`maskToken`）；日志只打印 shop_id 与到期时间，不打印 token 全值。
