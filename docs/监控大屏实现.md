# 监控大屏实现（开发视角）

> 面向**开发者**：按需采集调度、六域采集口径（含实测接口形态）、金额换算、告警引擎与数据存储。使用者视角见《[监控大屏](监控大屏.md)》；总体架构见《[架构](架构.md)》；开放平台调用与凭证失效语义见《[开放平台链路](开放平台链路.md)》。

## 1. 按需采集与调度

- 调度器（`monitor/scheduler.js`）**按需采集**：仅大屏页面打开时巡检——前端每 30s 心跳 `POST /api/monitor/presence`，服务端 75s 租约兜底；大屏在门户 iframe 内经 `postMessage('portal-tab')` 告知启停，直连页面则可见即采、隐藏即停。
- **巡检节奏**：在场时每 30s 巡检（每次重读授权店铺列表），按域间隔入队：**订单 10 分钟 / 商品 30 分钟 / 健康·广告·资金·售后 60 分钟**；同店串行、跨店并发 ≤3、失败按正常间隔退避；未配置 App 或无授权店铺时空转不发请求。
- **失效店铺跳过**：凭证失效（需重新授权）的店铺跳过采集（手动采集同样跳过并提示）；授权回调/刷新/删除经 `notifyAuthChanged()` 即时刷新店铺列表并补采。
- **监控店铺开关**：`/api/monitor/shops-config`（GET/POST）读写 `config.json` 的 `excludedShopIds` 排除名单（已授权店铺默认全部监控）。保存后 `scheduler.notifyConfigChanged()` 立即生效并补采一轮；未监控店铺不进巡检、不进大屏（总览 `excludedCount`），其未关闭告警自动关闭，并广播 `config` SSE 同步已开页面。
- **重点店铺筛选**：监控范围**先**按「开放平台」页勾选的**重点店铺**收窄（判定源 `openapi/store` 的 `getImportantIds`）——`registry.refreshShops` 只把重点店铺纳入注册表，非重点店铺不采集、不进大屏，其未关闭告警自动关闭；**一个都没勾选**时回落为全部已授权店铺。勾选变化经 `POST /api/openapi/shop-important` → `notifyAuthChanged()` 即时刷新店铺列表并补采。它与上面的「监控店铺开关」构成两级收窄（先重点店铺、再排除名单），大屏「监控店铺」面板里只列出重点店铺。详见《[开放平台链路](开放平台链路.md)》§4。

## 2. 采集要点（六域，接口形态为生产实测）

采集（`monitor/collectors/`，按域拆为 order/product/health/ads/funds/aftersale + parse/paging/catalog/shop-info）全部经 `callOpenApi`（GET），基础三域为生产实测：

- `order/get_order_list`：必填 `order_status + time_range_field + time_from/to + page_size`（≤15 天），`response.order_list` 仅含 order_sn（无时间字段），cursor 翻页；**订单年龄按 order_sn 的 YYMMDD 前缀按天估算**（`orderAgeBuckets`：今日 / 昨日及更早两档）。
- `first_mile/get_unbind_order_list`：`page_size + cursor`，`response.order_list + more/next_cursor`。
- `product/get_item_list`：必填 `item_status`（缺了报 product.error_unknown）+ `update_time_from/to + offset/page_size`，`response.item` 无库存字段、按 `next_offset` 翻页；库存逐商品调 `product/get_model_list`（`total_available_stock`）**按商品粒度合计**（全型号 0=断货、合计 ≤5=低库存），每轮抽查前 50 个热点商品。各域采集同步产出**结构化明细**（details[metricId].rows）：断货/低库存商品 ID+库存合计、待发货/取消/未交接订单号+创建日期、问题商品 ID+原因、处罚/扣分记录、打款/钱包流水、退货申请与差评内容等，进告警详情抽屉（见 §4）。
- 问题商品数读 `account_health/get_listings_with_issues` 的 `total_count`；健康指标读 `get_shop_performance` 的 `response.metric_list`（迟发货率/未完成率为百分数直接比较）；扣分记录数读 `get_penalty_point_history.total_count`。
- 注：`global_product/*` 为 merchant 作用域接口（签名/凭证形态不同），未接入。

**广告 / 资金 / 售后评价域（按官方文档接入，未经生产实测校准，使用侧口径见《监控大屏》§3）**：

- 广告域（60 分钟）：`ads/get_all_cpc_ads_hourly_performance` 仅 `performance_date`（**DD-MM-YYYY 单日**，≤今天），小时数组无分页——花费/成交额/点击当日聚合，CPC=花费/点击自算；`ads/get_total_balance` 无业务参数，`response.total_balance`（含付费+赠金）。
- 账户健康补充：`get_punishment_history` 必填 `punishment_status`（1=进行中 / 2=已结束），`response.total_count + punishment_list`（reason 1~5 为 Tier1~Tier5）；`get_listings_with_issues` 的 `listing_list` 仅含 `item_id + reason`（1=违禁/2=假冒/3=滥用/4=图片不当/5=信息不足/6=商城优化/7=其他优化），翻页聚合明细进告警消息。
- 资金域（60 分钟）：`payment/get_payout_detail`（`payout_time_from/to` ≤15 天 + `page_size/page_no` 必填，仅跨境）；`payment/get_escrow_list`（`release_time_from/to` 必填 + `page_no` 1 起，**仅返回已释放记录、无状态字段**）；`payment/get_wallet_transaction_list`（`page_no` 为 **offset 0 起**、`page_size` 必填 + `create_time_from/to` ≤15 天，仅本土店铺，`status`=FAILED/COMPLETED/PENDING/INITIAL 为资金域唯一状态来源——处理中/失败计数 + `current_balance` 余额）。
- 售后评价域（60 分钟）：`returns/get_return_list`（`page_no` 为 **offset 0 起**、`page_size` 必填 + `create_time_from/to` ≤15 天；`response.return[]` 字段名为 `reason`/`status` 无前缀，ReturnReason 31 个枚举中文映射见 `collectors/constants.js`）；`product/get_comment`（`cursor` 空串起 + `page_size` 1~100 游标分页，`item_id` 可选——优先全店扫描、失败降级为商品清单 top 20 逐商品扫描；响应 `item_comment_list + more + next_cursor`，单接口最多 500 条）。
- 权限降级：某域全部子调用因权限不足失败（`isPermissionDenied` 按 permission/not authorized/无权 等文案判定）时标记 `unsupported`——按正常间隔退避、**不计数失败、不触发系统自检告警**，meta 记录原因供店铺卡「—」悬浮提示；开通权限后自动恢复。

## 3. 金额换算与展示

- **金额换算（`monitor/currency.js`）**：金额类指标（单位「元」）的**规则阈值一律按人民币配置与比较**——引擎在 `ingest`/`maintain` 评估前经 `toRmb` 换算（规则面板有提示）；大屏展示全局切换「当地货币（默认）/ 人民币」（`config.json` 的 `currencyMode`，`GET/POST /api/monitor/currency-config`），矩阵/趋势/告警消息在路由层按当前模式换算渲染（告警消息经 `engine.renderAlertMessage` 重渲染）；快照/告警 `current` 一律存**当地货币原始值**。
- 店铺币种由 `get_shop_info` 的 region 自动识别（首次采集写入 meta.currency，未知按人民币）；汇率每日从免费 keyless 接口（open.er-api.com/v6/latest/CNY）更新并缓存 `rates.json`（24h），失败回退内置静态汇率表（`STATIC_RMB_RATES` 近似值）；在线刷新仅在有已授权店铺时触发（测试环境离线）。

## 4. 告警引擎与授权失效

- 规则引擎（`monitor/rules.js` + `engine.js`）：静态阈值三级分级（P0/P1/P2，direction 支持 up/down，阈值缺省则该级不触发）；生命周期为触发→去重计数→阈值升级→**回稳自动移出告警流**→人工**删除**（回稳清理与采集恢复由引擎直接 `splice` 移除该条并广播 `change:'delete'`；`engine.deleteAlert` 亦从内存与落盘移除、广播 `change:'delete'`；内部收尾仍用 `closeAlert` 的「终端态保留」，如停用监控场景），P2 持续 24h 自动升 P1；系统自检按连续失败次数定级（1→P2、2→P1、≥5→P0）。`engine.ingest` 第 5 参 `details`（`{ metricId: 明细 }`）兼容两种形态：纯文本（拼入告警消息，旧形态）与 `{ text, rows }` 对象（text 拼入消息；rows 为结构化明细行 `[{ id, title, sub }]`，存入告警的 `detailRows`，随 `/api/monitor/alerts` 与 SSE 下发，供大屏告警「详情」抽屉展示，单条上限 200 行、无明细时自动清空不残留）。告警只在大屏展示（不接 IM）。
- **阈值「留空 = 该级别不触发」必须用 `null` 传递**（前后端契约，改动前先读 `store.setRuleOverrides` 与 `rules.mergeRules` 的注释）：`store` 对 `null` 原样保留，`mergeRules` 遇 `null` **删除**该级默认阈值；**只有不传该级别才保留默认**。前端 `saveRules` 必须把 `''` / `null` / `undefined` 统一转成 `null`——否则用户清空输入框等于没改，默认阈值会「复活」。
- **系统自检告警（`engine.systemFail`）同样受规则 `enabled` 约束**：`system.collect_fail` 被关闭后不再产生新告警，且**已存在的直接从告警流移除**——`system` 域没有别的回稳信号（`maintain` 的回稳检测只对业务域生效），不移除会永远挂在告警流里。
- 授权失效呈现：店铺标记「需重新授权」时关闭其「采集连续失败」告警；大屏横幅显示「N 家店铺待重新授权」+ 一键跳「开放平台」按钮（iframe 经 `parent.postMessage` 切 Tab），店铺卡置灰；总览 `reAuthCount` 供前端使用。

## 5. 数据存储与 SSE

- 数据（`monitor/store.js`）：`server/data/monitor/` 下 `rules.json`（阈值覆盖，金额口径人民币）、`config.json`（排除名单 + `currencyMode`）、`alerts.json`（告警，防抖落盘）、`meta.json`（店铺名/币种/采集状态）、`rates.json`（汇率缓存）、`snapshots/{shopId}/{metric}/YYYY-MM-DD.json`（保留 90 天，金额存当地货币原始值）；全部 gitignored，不含凭证。
- SSE（`/api/monitor/events`）：告警变更 / 采集结果 / 规则更新 / 店铺配置变更四类事件，迟到连接自动回放最近 200 条；前端 30s 兜底轮询。

## 6. 大屏交互接口补充（阈值建议 / 趋势环比 / 告警删除）

- **阈值分位数建议**（`GET /api/monitor/rule-suggestions?days=30`，`monitor/suggest.js` 的 `buildRuleSuggestions`）：按**已启用监控且授权正常**的店铺读各自快照样本（金额类先 `toRmb` 换算成人民币，与阈值比较口径一致），升序取分位数——up 方向取 P75/P90/P97、down 方向取 P25/P10/P03，按单位取整（`%`/`分`/`倍` 保留 2 位，其余取整）；同时给出「当前阈值历史命中率」（样本落进任一触发级别的占比，长期偏高＝阈值过于敏感）与 `flat`（建议各级相等＝数据无波动）。约束：样本 <20 不给建议、`system` 域不参与、up 方向建议落到 0 视为无效。**只读快照、不落盘、不自动应用**——前端「采用」只把建议填进输入框，仍需用户点「保存」。
- **趋势环比**（`GET /api/monitor/trend?...&compare=1`）：`store.readTrend(shopId, metric, days, offsetDays)` 新增 `offsetDays`——`offsetDays=days` 取「更早 days 天」的上一周期采样点（与当前窗口不重叠），经同样金额换算后随 `prevPoints` 返回；前端 `trend-chart.js` 改用 **time 轴**承载两条序列，并按「末点对齐」把上一周期平移到当前周期（比较「现在 vs 上一周期同一进度」）。
- **告警删除（单条 / 批量）**（`POST /api/monitor/alert-action`，`action: 'delete'`）：body 用 `{ id }` 或 `{ ids: [...] }`，逐条调用 `engine.deleteAlert`（从内存与落盘移除、广播 `change:'delete'` 让其它已开页面同步移除），返回 `{ alert, alerts, count }`（`alert` 保留首条）——**响应里的告警副本同样带 `change:'delete'`**（SSE 事件与 HTTP 响应形态必须一致，前端 `upsertAlert` 据此在响应路径也移除；不带的话发起页面会把刚删的告警塞回列表，即「删除后闪回」bug）；找得到的才计数，全找不到回 400「告警不存在」，空 id 回 400「缺少告警 id」。大屏不再提供「确认 / 关闭」，删除是唯一人工操作。
