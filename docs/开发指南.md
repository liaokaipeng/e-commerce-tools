# 开发指南（面向开发者）

> 本文档面向**开发者**：说明仓库架构、模块约定、如何新增工具、如何扩展测试与调试。
> 面向最终用户的操作教程见《[新手入门指南](../新手入门指南.md)》，仓库概览见 [README](../README.md)。

## 1. 架构总览

单服务、单端口（8765）、单网页。后端一个 Node HTTP 服务托管前端构建产物（`frontend/dist`），前端是 Vue3 + Element Plus 多页应用，按 Tab 切换三个工具：

| 工具 | 后端模块 | 前端页面 | 链路 |
|------|----------|----------|------|
| TikTok 无水印下载 | `tiktok.js` | `frontend/src/tiktok/` | 直连解析页面水文数据 → 第三方接口兜底 → 分地址下载 |
| Shopee 竞价导出 | `bidding.js` | `frontend/src/bidding/` | 扩展推 Cookie → 调 seller 接口拉获胜数据 → ExcelJS 导出 |
| Shopee 视频批量上传 | `video.js` | `frontend/src/video/` | 扩展抓凭证 → preupload/分片/PUT/merge/report → video/create 发布 |

浏览器扩展（`extension/`，MV3）负责两类凭证抓取：竞价 Cookie（推 `/api/cookie`）与视频上传凭证（推 `/api/creds`）。

## 3. 后端约定

- **CommonJS**：`require` / `module.exports`，不要混用 ESM。
- **路由注册模式**：业务模块导出 `register({ get, post })`，由 `main.js` 在启动前统一调用。

```js
function register({ get, post }) {
  get('/api/xxx/status', handleStatus);
  post('/api/xxx/start', handleStart);
}
module.exports = { register };
```

- 路由处理函数签名 `(req, res, url)`，`url` 为 `new URL(...)`（含 query）。
- 响应统一走 `sendJson(res, status, data)`；请求体读取用 `readBody(req)`（默认 2MB 上限，超限拒绝）。
- 出站请求统一走 `lib/http.js` 的 `request`；需要跨请求会话 Cookie 时 `useJar: true`（视频上传分片链路依赖）。
- 凭证不入库：`bidding-session.json` / `video-session.json` / `settings.json` 均 gitignored，日志不完整打印 Cookie/Authorization。
- 不改入口/端口/结构；必须改时同步更新 `启动.bat`、`README.md`、`AGENTS.md` 与本文档相关小节。

## 4. 新增一个工具/模块的步骤

1. 新建 `xxx.js`，实现 `register({ get, post })` 注册路由；需要纯函数时放入 `lib/` 便于单测。
2. 在 `main.js` 顶部 `require` 并调用 `xxx.register({ get, post })`。
3. 前端在 `frontend/` 新增一个多页入口（`xxx/index.html` + `src/xxx/`），并在 `vite.config.js` 的 `rollupOptions.input` 登记。
4. 门户页 `frontend/src/portal/App.vue` 增加 Tab。
5. 在 `test/api.test.js`（接口）与 `test/unit.test.js`（纯函数）补充用例。
6. 更新 `README.md`（目录结构 / API 表）、`AGENTS.md`、本文档。
7. 跑 `node test.js` 全绿后提交。

## 5. 视频上传模块要点

- **站点区分**：`cn`（跨境，分片 + merge，域名/参数见 `video.js` 顶部常量）；`ph`（本土菲律宾，单次 PUT + task 发布，配置在 `SITES.ph`）。
- **凭证解析（跨境）**：`resolveCnAuth` 唯一入口，优先级：本地已抓凭证（账号级通用，取有效期最长）→ Cookie 换取 → 报错引导手动上传。
- **成功码**：solutions 系列接口成功码为 `200000`（非 0），有 `post_id` 即发布成功；老接口可能返回 0。
- **AK/SK 与加密**：`preupload` 返回的 `access_key`/`token` 为 AES-128-CBC 加密（key=`shopee_vod_`+biz 左补 0 到 5 位，iv 固定），用 `lib/video-utils.js` 的 `decryptVodToken` 解密；ph 的 S3 PUT 用 `awsSigV4` 签名。
- **SSE 消息流**：`POST /api/start` 返回 jobId，`GET /api/events?jobId=` 收事件（`row-start` / `step` / `row-done` / `row-error` / `finished` / `fatal`）。服务端对每个 job 缓存事件，**迟到连接自动回放**：任务可能在 SSE 连接建立前就结束（如首行校验秒失败），无回放会让前端一直卡在上传中。
- **行校验**：`validateUploadRow`（在 `lib/video-utils.js`）先于一切网络请求执行，文件不存在等错误秒失败。

## 6. 浏览器扩展

一个扩展（MV3）同时负责两类凭证：

- **竞价**：popup 点按钮 → 推 Cookie 到 `/api/cookie`，存 `bidding-session.json`。
- **视频上传**：`background.js` 监听 `webRequest`，按站点（`shopee.cn` / `shopee.ph`）抓 `Authorization` / `Cookie` / `shop_id` / `userId` → 推 `/api/creds`，存 `video-session.json`；凭证同时缓存在 `chrome.storage.local`，本地服务未启动不丢，抓到新请求时整包重推。

改扩展注意：`manifest.json` 的 `host_permissions` 与 `FILTER` 需覆盖对应 `shopee.{cc}` 域；`detectSite` 会忽略 `shopee.sg`（路由/指标域名）。

## 7. 测试

```bash
node test.js        # 或 npm test；全部通过即正常（退出码 0）
```

两类测试，结果汇总一份：

1. **单元测试** `test/unit.test.js`：纯函数，不启动服务、不访问真实站点。覆盖 `lib/video-utils.js`（md5/etag/AES 解密/auth exp/SigV4/MP4 探测/行校验）、TikTok 链接处理与代理检测、竞价金额换算。
2. **接口冒烟测试** `test/api.test.js`：以 `PORT=8865` 临时启动服务，验页面静态资源、各模块 API 路由、SSE 端到端（含迟到回放）、404 兜底。**不访问真实站点**。

`test/helpers.js` 提供 `t(name, ok, detail)` 断言、`req(method, path, body)` 请求封装、`startServer()`（自动备份并原样恢复 `bidding-session.json` / `video-session.json` / `settings.json`，内含用户真实凭证，测试结束后不能删除）。

新增测试用例：
- 纯函数 → 在 `unit.test.js` 的 `run()` 里追加 `t(...)`。
- API 路由 → 在 `api.test.js` 的 `run()` 里用 `req` / `readSSEUntil` 追加，注意勿触发真实网络调用。

## 8. 调试小贴士

- 前端开发：`cd frontend && npm run dev`（5173，`/api` 已代理到 8765）。
- 改后端后热重启：停掉 `node main.js` 再启即可；`启动.bat` 会先构建前端。
- 视频上传排障看 SSE 日志的 `step` 事件；凭证问题先看 `GET /api/creds` 返回的站点结构。
- 改 `lib/video-utils.js` 后必跑 `node test.js` 验证单元测试。
