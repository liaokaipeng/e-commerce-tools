# 开发指南（面向开发者）

> 本文档面向**开发者**：说明后端约定、如何新增工具、如何扩展测试与调试。
> 架构与目录结构见《[架构](架构.md)》；监控大屏的实现要点见《[架构](架构.md)》第 8 节、使用者视角见《[监控大屏](监控大屏.md)》；仓库概览与快速开始见 [README.md](README.md)；最终用户操作见《[新手入门指南](../新手入门指南.md)》。

## 1. 后端约定

- **CommonJS**：`require` / `module.exports`，不要混用 ESM。
- **路由注册模式**：业务模块导出 `register({ get, post })`，由 `main.js` 在启动前统一调用。

```js
function register({ get, post }) {
  get('/api/xxx/status', handleStatus);
  post('/api/xxx/start', handleStart);
}
module.exports = { register };
```

- 路由处理函数签名 `(req, res, url)`，`url` 为 `new URL(...)`（含 query）。
- 响应统一走 `sendJson(res, status, data)`；请求体读取用 `readBody(req)`（默认 2MB 上限，超限拒绝）。
- 出站请求统一走 `server/lib/http.js` 的 `request`；需要跨请求会话 Cookie 时 `useJar: true`（视频上传分片链路依赖）。
- 凭证不入库：`bidding-session.json` / `video-session.json` / `openapi-session.json` / `settings.json` 均 gitignored（统一存放在 `server/data/`），日志不完整打印 Cookie/Authorization/token。
- 对接 Shopee 开放平台接口前先查 `shopee_api_doc/`（开发者指南与 API 参考 v2 整站目录，中文版，含官方页面链接）；官方更新后跑 `node shopee_api_doc/_tools/fetch-docs.js` 刷新。调官方 Open API 统一走 `server/openapi/client.js` 的 `callOpenApi`（自动签名/token/刷新），不要自行拼签名。
- 不改入口/端口/结构；必须改时同步更新 `启动.bat`、`docs/README.md`、`docs/架构.md`、`AGENTS.md` 与本文档相关小节。

## 2. 新增一个工具/模块的步骤

1. 新建 `server/xxx.js`，实现 `register({ get, post })` 注册路由；需要纯函数时放入 `server/lib/` 便于单测。
2. 在 `server/main.js` 顶部 `require` 并调用 `xxx.register({ get, post })`。
3. 前端在 `frontend/` 新增一个多页入口（`xxx/index.html` + `src/xxx/`），并在 `vite.config.js` 的 `rollupOptions.input` 登记。
4. 门户页 `frontend/src/portal/App.vue` 增加 Tab。
5. 在 `test/api.test.js`（接口）与 `test/unit.test.js`（纯函数）补充用例。
6. 更新 `docs/README.md`（API 表）、`docs/架构.md`（目录结构 / 链路）、`AGENTS.md`、本文档；新增的 Shopee 官方接口资料同步到 `shopee_api_doc/`。
7. 跑 `node test.js` 全绿后提交。

## 3. 测试

```bash
node test.js        # 或 npm test；全部通过即正常（退出码 0）
```

两类测试，结果汇总一份：

1. **单元测试** `test/unit.test.js`：纯函数，不启动服务、不访问真实站点。覆盖 `server/lib/video-utils.js`（md5/etag/AES 解密/auth exp/SigV4/MP4 探测/行校验）、TikTok 链接处理与代理检测、竞价金额换算、取消竞价待改进列表解析（`bidding-cancel.extractImprovementItems`）、开放平台签名与打码（`server/lib/openapi-utils.js`），以及任务取消逻辑（`video._test` 确定性驱动 `processJob`）。
2. **接口冒烟测试** `test/api.test.js`：以 `PORT=8865` 临时启动服务，验页面静态资源、各模块 API 路由、SSE 端到端（含迟到回放）、任务取消（契约 + 进行中取消）、开放平台登录（未配置/保存/打码/删除幂等/回调页，不触达真实站点）、404 兜底。**不访问真实站点**。

`test/helpers.js` 提供 `t(name, ok, detail)` 断言、`req(method, path, body)` 请求封装、`startServer()`（自动备份并原样恢复 `server/data/bidding-session.json` / `server/data/video-session.json` / `server/data/openapi-session.json` / `server/data/settings.json`，内含用户真实凭证，测试结束后不能删除）。开放平台凭证在服务启动时读入内存，故测试服务经 `OPENAPI_SESSION_FILE` 环境变量指向独立临时文件隔离，接口测试全程不触达用户真实 `openapi-session.json`，也不触达真实站点。

新增测试用例：

- 纯函数 → 在 `unit.test.js` 的 `run()` 里追加 `t(...)`。
- API 路由 → 在 `api.test.js` 的 `run()` 里用 `req` / `readSSEUntil` 追加，注意勿触发真实网络调用。

其余无自动化：TikTok 下载 / 竞价导出 / 取消竞价 / 视频上传按真实流程手测。

## 4. 调试小贴士

- 前端开发：`cd frontend && npm run dev`（5173，`/api` 已代理到 8765）。
- 改后端后热重启：停掉 `node server/main.js` 再启即可；`启动.bat` 会先构建前端。

- 改 `server/lib/video-utils.js` 后必跑 `node test.js` 验证单元测试。

### 4.1 开放平台接口报参数错误怎么查（经验沉淀）

网关的 `error_param` 类报错**经常是误导性的**：参数位置/类型/签名基串任一不符，报错文案会在多条错误间“连锁漂移”（实测遇到过 `the format of shop_id parameter is wrong` → `It should have partner_id in the request body` → `Wrong sign` 依次出现，真实原因却是签名基串与参数类型）。**不要按报错文案字面去改**，按下面顺序排查：

1. **先查文档**：`shopee_api_doc/`（开发者指南 + API 参考 v2 整站目录，含每个接口的官方页面链接）→ 点开对应接口的官方页面核对参数名、必填项、分页字段（如 `order/get_order_list` 必填 `time_range_field + page_size`，`product/get_item_list` 缺 `item_status` 会报含义不明的 `product.error_unknown`）。官方更新后跑 `node shopee_api_doc/_tools/fetch-docs.js` 刷新目录。
2. **最小参数组合逐变体验证**：先去掉所有业务参数只留公共参数，确认签名正确（sign 通过后报错会进入下一层校验，可据此逐层定位）；再逐个加参数。
3. **参数类型**：v2 网关对 JSON body 里的 id 类参数（`partner_id` / `shop_id`）要求**数字类型**，字符串会报格式错；query 参数一律字符串。
4. **方法约定**：查询类接口（get_*/search_*）用 GET（全参数放 query），写操作/换 token 用 POST（公共参数 query、业务参数 body），方法用错网关直接 404。
5. **签名基串**：业务接口 `partner_id + api_path + timestamp + access_token + shop_id`；`access_token/get` 刷新接口特殊（只拼 `partner_id + api_path + timestamp`，详见《[架构](架构.md)》6.2 节实测结论）。
6. **真实接口验证只做只读 GET**，且优先用测试/沙箱环境；生产联调完记得清掉本地测试数据（如 `server/data/monitor/`）。

实测接口形态沉淀在《[架构](架构.md)》第 6.2、6.3、8 节（含监控大屏三域的参数与响应结构、token 刷新绑定语义、网关误导性文案清单）。
